## 1. 프로젝트 목표 / 확정 사항

### 목표
현재 개인 포트폴리오 대시보드를 **투자 상황실 + 자산관리 + 시장 분석 + 과거 유사 시장 + 전략 연구실**이 연결된 반응형 투자 의사결정 지원 웹앱으로 확장한다. 실제 주문 자동 실행 및 투자수익 예측 서비스는 만들지 않는다.

### 변경 불가능한 핵심 제약
1. **주 사용 기기**: 스마트폰과 태블릿. 스마트폰에서는 **자산 조회 및 매수·매도 거래 기록 작성/수정**이 가장 중요하다. 태블릿에서는 **시장 지표 분석, 비교 차트, 과거 유사 시장, 전략 연구**가 가장 중요하다.
2. **테마**: 라이트 모드 + **다크 모드 필수**, 사용자 전환 및 설정 유지. 기본 시각적 스타일은 A+ (`웜그레이 배경, 흰 카드, 딥 네이비, 세이지 그린, 앰버 경고`)이다. 기존 자산관리 화면도 같은 디자인 시스템으로 점진적 통일 가능.
3. **무료 클라우드**: 기존 Supabase Free 프로젝트 **하나만 사용**. 추가 유료 DB/호스팅/금융 API 의존을 필수 요구로 만들지 않는다. 사용자가 공유한 조직 사용량은 당시 28/500MB였으며 프로젝트별 실제 사용량은 재확인.
4. **로컬 PC 의존 최소화**: 개발에는 PC를 사용하지만, **실사용을 위한 상시 로컬 서버, 로컬 DB, 로컬 파일 저장 요구 금지**. 기본 기능은 브라우저에서 접근 가능해야 한다. 일반 계산은 웹 브라우저(필요시 Web Worker)에서 수행. 브라우저 종료 시 진행 중 계산은 취소될 수 있다.
5. **기존 코드·데이터 보호**: 지금 정상 동작하는 자산관리, 거래기록, 전략 규칙 및 Supabase 데이터의 기능 회귀 방지. 스키마 변경 시 마이그레이션/백업·롤백 방법 먼저 승인.
6. **데이터 신뢰**: UI용 합성 데이터와 실제 데이터를 명확히 구분. API 오류/데이터 누락/지연을 숨기지 말 것. 백테스트는 실제 연산 엔진 검증이 끝나기 전 '투자 판단용 정확한 성과'로 주장하지 말 것.
7. **공정한 전략 비교**: 같은 원천 데이터, 배당/비용/체결 시점 규칙을 모든 전략에 동일하게 적용. QLD 등 레버리지 ETF의 일일 복리 효과 반영, 미래 정보 사용 금지.

### 기존 프로젝트 관련 알려진 배경 (현행 코드에서 반드시 재검증)
- 저장소: `https://github.com/qqwwqq113-blip/investment_platform.git` (사용자 기존 프로젝트)
- 이전 탐색 시 HTML/CSS/JS 기반, `index.html`, `app.js`, `finance.js`, `worker.js`, `styles.css`, Supabase 관련 구성, `package.json`, 테스트 파일이 존재했음. 실제 브랜치/파일명/설정은 먼저 확인할 것.
- 기존 운용 전략: 목표 QQQ 10% / QLD 70% / SGOV 20%; QQQ MDD -20%일 때 SGOV 절반(목표 비중 10%p 상당)을 QLD 매수, -30%일 때 나머지(10%p 상당) 매수; QLD 비중 85% 이상이면 목표 비중으로 리밸런싱. 기존의 실제 구현 semantics를 검토해 임의 변경하지 않는다.

## 2. 목업을 디자인 기준으로 사용하는 방법

### 제공 파일
`investment_intelligence_Aplus_demo.html` — 클릭 가능한 단일 HTML 시연본(합성 데이터).

### 확인된 페이지 / 체험 요소
- `overview` / `page-overview`: 통합 상황실, 포트폴리오 차트 기간, 카드 편집/저장/초기화, 관련 화면 이동
- `portfolio` / `page-portfolio`: 자산·비중 요약, 현재 전략의 연구실 가져오기, 규칙 백테스트 연결
- `market` / `page-market`: 거시지표 비교와 위험 가중치 조정/초기화
- `analogs` / `page-analogs`: 과거 유사 시장 가중치와 사례 탐색, 전략 연구실 이동
- `lab` / `page-lab`: 자산배분, 현금 흐름/백테스트, 후보 탐색, 스트레스 테스트, 결과 저장
- `settings` / `page-settings`: 사용자 표시 설정과 데이터 정책

### 목업의 한계 (반드시 개발 요구사항으로 보강)
- **거래 내역 입력/수정/삭제를 위한 휴대폰 최적화 플로우는 목업에 충분히 표현되어 있지 않다**. 기존 시스템의 실제 거래기록 필드와 검증을 확인하고 이를 최우선으로 설계한다.
- 현재 목업 스타일은 라이트 중심. **다크모드를 새로 구현**한다.
- 합성 수익률/시장 위험/과거 유사 구간/최적화 수치는 UI 시연용이다. 운영 데이터 또는 검증된 투자 계산으로 그대로 복사하지 말 것.
- A+ 컨셉을 유지하되 화면의 밀도·버튼 크기·탐색 방식은 **모바일/태블릿에 맞춰 재디자인**한다. 목업 DOM/CSS 구조를 그대로 복붙하는 것이 목표가 아니다.

## 3. 화면별 UX 명세

### UX-01 모바일 홈 / 통합 상황실 (F-001)
- 화면 폭 320~480px 중심. 먼저 총자산·오늘/기간 손익·최근 거래·전략 신호 노출.
- **하단 고정 네비게이션** 권장: `홈`, `자산`, `거래 등록`, `시장`, `더보기`. 실제 메뉴는 탐색성 테스트 후 조정. 태블릿에서는 사이드 내비게이션 또는 상단 탭 사용 가능.
- QQQ MDD, 위험 점수, 시장 지표는 작은 요약 카드로 표시; 탭 시 상세 화면.
- 사용자가 카드 순서/표시 여부를 바꿀 수 있음. 기본 레이아웃과 복원 버튼 제공. 무의미하게 복잡한 자유 크기 조절 위젯 기능은 제외.
- 카드에는 기준 날짜/통화, 샘플 여부, 미갱신 여부를 표시.

### UX-02 모바일 자산관리 / 거래기록 (F-002~F-006) — 최우선
- 현재 계좌/총평가액/종목별 현재 비중/평단가·보유수량·평가손익을 좁은 화면에서 줄바꿈·가로 스크롤 강요 없이 확인.
- 최근 거래는 날짜, 티커, 매수/매도, 수량, 단가, 금액 중심의 세로 카드 목록. 기간/종목/매수·매도 필터 제공.
- 홈과 자산 화면 모두에서 **거래 등록**으로 1탭 내 진입 가능한 CTA 제공.
- **매수/매도 기록 폼**: 기존 DB 필드와 맞는 계좌, 거래일, 종목, 매수/매도, 수량, 단가, 수수료, 통화, 메모(지원되는 필드 확인). 금액 자동 계산. 입력 시 숫자 키패드, 넓은 터치 영역(최소 44×44 CSS px 권장), 오류 메시지, 저장 상태.
- 매도 가능 수량·0 이하 금액·중복 제출·네트워크 실패 검증. 거래 입력 시 원본 거래 내역과 계산된 보유량/성과가 연결됨.
- 거래 수정/삭제는 확인 단계, 저장 성공/실패 안내, 취소/복구 가능한 흐름을 제공. 기존 회계 처리 기준 확인 후 구현.
- 저장 중 버튼 비활성화, 저장 완료 후 최신 목록과 평가 결과 갱신, 네트워크 실패 시 임의 저장 성공 표시 금지.
- 실제 계정 보유 종목을 전략 연구실로 가져가되 해당 동작이 원본 운용 설정을 수정하지 않음.

### UX-03 태블릿 시장 분석 (F-007~F-010)
- 768~1200px 우선. 화면을 `지표 선택·필터(사이드 패널)` + `큰 비교 차트` + `해석·원천 데이터·위험 기여 카드`로 구성.
- 핵심 지표 20~30종부터 시작, 2~3개 지표 비교, 기간 선택, 정규화(예: 시작점=100), 단위/보조축 혼동 방지.
- 종합 위험점수 0~100과 분야별 점수 표시, 가중치 수정/초기화, 변경 결과 즉시 재계산. 점수 = 실제 하락 확률이 아님을 명시.
- 출처, 관측 시점, 발표 시점, 데이터 갱신 시점, 결측 여부 표시. 미래정보를 사용하는 분석을 방지.

### UX-04 태블릿 과거 유사 시장 (F-011)
- 핵심 시장지표 3~5개 선택, 기본 가중치 및 사용자 수정, 유사 사례 목록, 당시 특징 및 이후 3/6/12개월 사례 성과를 시각화(데이터 확보 시).
- 대상 당시 공개되지 않았던 정보와 미래 데이터를 유사도 계산에 사용하지 않음. 사례가 적으면 샘플 수와 신뢰 한계 표시.
- 선택한 시장 사례를 전략 연구실로 전달. 데이터가 없다면 명시적 미지원 상태 출력.

### UX-05 태블릿 전략 연구실 (F-012~F-017)
- 큰 화면에서 좌측 `투자자산/투자금/매매규칙/비용/세금/기간 설정`, 우측 `결과 성과 카드/곡선/하락률/비교표`로 구성.
- 기본 ETF 10~20개부터 시작. 주요 ETF 기본 제공 + 사용자가 종목 추가 가능은 **장기 확정 방향**이나, 1차는 데이터 제공 범위 내 제한적 추가로 시작. 자유 추가 UI 제공 시 데이터 확보 불가 상황 처리.
- 일시금/적립식/혼합형, 자산배분, 정기 리밸런싱, QQQ MDD 조건, 세전+단순 세후 비교.
- 3개 전략까지 비교. CAGR, MDD, Sharpe, Calmar, 최종자산, 외부 현금 흐름 구분. TWR(전략성과)과 XIRR(납입시점 효과) 구분.
- 경량 자동 최적화(권장 시작 한도: 투자자산 최대 5종/조합 100~300개/가중치 단계 10% 등은 **성능 검증 전 제안값**) 및 상위 결과 요약. 자동 탐색은 UI 차단을 피하도록 Web Worker/작업 취소/진행도 검토.
- 과거 위기 재현과 단순 충격 시나리오는 2차 기능. 실제 ETF 상장 전 가상 백필은 표시하고 실제 가격과 혼합하지 않는다.
- 저장 시 전략 입력조건·데이터 범위·계산 버전·요약 결과만 DB에 보관하고 중간 전체 조합 결과는 저장하지 않는다.

### UX-06 테마/설정 (F-018~F-020) — 필수
- **라이트/다크/기기 설정 따름(System)** 3가지 선택지.
- `prefers-color-scheme`에 따른 초기 결정, 사용자 명시 선택 시 우선 적용, 새로고침/라우팅 및 동일 계정 다른 기기 동기화(기존 사용자 설정 스키마/로그인 구조 확인 후). 초기 로딩에 잘못된 테마가 번쩍 나타나는 FOUC 최소화.
- CSS 변수(디자인 토큰)로 전체 화면 및 차트 테마 일원화. 하드코딩된 배경·글자색을 정리하여 혼합 테마 방지.
- 라이트 기준 예시: `--bg: #f1f4f6`, `--surface: #ffffff`, `--navy: #17354a`, `--accent: #298a74`, `--warning: #bf872f`.
- **다크 권장 시안(제안, 승인 필요)**: 배경 `#101a24`, 카드 `#182735`, 기본 글자 `#e9f1f5`, 보조 글자 `#9eb1c0`, 주요 액센트 `#67c9aa`, 경고 `#e0b15c`, 경계 `#344454`. A+ 아이덴티티는 유지하면서 단순 반전은 피함.
- 차트 선·툴팁·표·폼·선택 상태·비활성 버튼·경고·상승/하락 색상 모두 테마 호환. 색상뿐 아니라 부호·아이콘·문구로 상승/하락 구분.
- 명암 대비 WCAG AA에 준하는 텍스트·주요 조작 가독성 점검, 키보드 포커스 표시, OS 글자 크기 확대 대응.
- 대시보드 카드 순서/표시 설정 저장. Free DB 저장량과 시장 데이터 갱신 상태도 설정 화면에 표시.

### 반응형 브레이크포인트(제안·조정 가능)
- 0~599px: 스마트폰 — 단일 열, 하단 네비게이션, 거래 입력 중심, 큰 터치 영역, 스크롤 표 대신 카드.
- 600~1023px: 태블릿 세로 — 1~2열, 압축된 분석 필터, 차트 우선.
- 1024px 이상: 태블릿 가로/PC — 2~3열, 고밀도 시장·전략 분석, 사이드 내비게이션.
- iOS Safari / Android Chrome / 데스크톱 Edge·Chrome을 실제 크기에서 확인. 노치 safe-area, 가상 키보드, 회전 대응.

## 4. 데이터 / 인프라 / 계산 원칙

### 저장 구조
- 기존 Supabase Free 1개 유지. 무제한 시계열 데이터 저장 금지.
- 영구: 거래기록, 포트폴리오 정보, 투자 전략/사용자 설정, 대시보드 레이아웃, 저장한 백테스트 조건·요약 성과.
- 선택적 캐시: 핵심 ETF/거시지표 데이터와 위험 점수. 원본 API 제공 범위와 저장·재배포 약관 확인.
- 비영구: 개별 자동 최적화의 전체 조합, 대규모 중간 일별 결과.
- DB 목표 300MB 미만은 **운영상 제안**, 공식 한도 아님. 데이터 사용량/성장률 경고 및 정리 정책 수립.
- 기존 Worker/API 라우트를 재사용하거나 최소한으로 확장. API 키는 서버 측 환경 변수로만 보관. 브라우저에 Supabase `service_role` 등 고권한 키 노출 절대 금지.
- 외부 시세 공급 API는 호출 제한·사용권·장애 대책 검증. 필요시 데이터 공급처를 교체할 수 있는 adapter 설계.

### 백테스트 계산 엔진
- 일별 종가를 보고 동일 종가에 거래하는 룩어헤드 금지: 신호 관측/체결 시점 분리.
- 배당 처리 방식이 조정 주가/총수익률 시계열과 이중 계산되지 않게 분리.
- 수수료, 슬리피지, 환전, 현금 흐름, 리밸런싱, 세전/단순 세후 가정을 전략마다 동일 적용.
- 단순 세후 모형은 실제 신고세액 아님. 세율/과세시점/실현손익/기준통화·원화환산 가정 노출.
- QLD/TQQQ 등의 일일 레버리지 효과는 실제 ETF 시계열 또는 명시적으로 검증된 모형으로 처리. 단순 `QQQ 누적 수익률 × 2` 금지.
- 기존 자산관리의 수익률 및 리밸런싱 로직은 테스트 후 재사용하고 계산 규칙이 다른 경우 차이를 문서화.
- 과거 유사 시장 탐색은 데이터 기준일 당시 관측 가능했던 데이터만 사용하고 샘플 중복, 발표 시차에 주의.

## 8. Codex 실행 지침 / 제출 산출물

### 승인 전 준비할 것
1. 실제 저장소/의존성/DB 접근 경로/테이블/테스트 구성 현황 보고.
2. **차이 분석**: 기존 자산관리 기능 vs 목업의 자산관리 표현; 모바일 거래 UI 누락 부분 목록화.
3. 모바일 360px/390px와 태블릿 768px/1024px 대표 **클릭 가능한 UI 시안**. 라이트·다크 두 테마 모두 제시.
4. DB 추가·수정이 필요한 테이블/칼럼 목록 및 최소 마이그레이션 제안. RLS와 백업 전략.
5. Phase별 변경 파일, 작업 수, 예상 리스크, 검증 명령 및 수동 검수 항목.
6. 최종 확인이 필요한 결정이 있으면 질문하되, 이미 정해진 방향은 되묻지 말 것.

### 승인 후 개발 원칙
- 작은 단위로 수정 후 코드·단위 테스트·모바일 화면 검증.
- 기존 계좌/거래 데이터 보존, DB 스키마 파괴적 변경 금지.
- 사용자의 기존 작업물 직접 덮어쓰기 전에 diff·마이그레이션 영향 설명.
- 테스트가 없던 계산 로직은 **합성 기준 케이스**로 회귀검증 추가.
- 화면마다 로딩/빈 화면/오류/다시 시도 상태 구현.
- API 키 등 비밀정보는 커밋/로그에 남기지 않음.
- 각 단계 마무리 때 변경파일 목록, 검증 결과, 잔여 리스크, 다음 단계 제안 보고.
