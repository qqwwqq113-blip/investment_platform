# Phase 1B 변경 명세

## 목표

스마트폰에서 보유 자산을 확인한 뒤 거래 등록·수정·삭제까지 안전하게 완료하는 핵심 자산관리 흐름을 제공한다. 기존 거래 원장, 포트폴리오 계산, 서버 API 및 데이터베이스 스키마는 유지한다.

## 구현 범위

- 보유 자산 상세 화면의 종목별 빠른 매수·매도 진입
- 모바일 하단 대표 CTA에서 거래 등록 폼까지 한 번의 탭으로 진입
- 선택 종목의 현재 보유수량 및 매도 가능 수량 안내
- 수량·단가 입력에 따른 예상 거래금액과 거래 문장 미리보기
- 수량, 단가, 거래 일시, 정산 잔액의 필드별 오류 안내
- 보유수량 초과 매도 및 정산 잔액 초과 매수의 클라이언트 사전 차단
- 저장 중 버튼 상태와 동일 화면 중복 제출 방지
- 수정 중 상태, 대상 거래 정보, 수정 전용 CTA 표시
- 삭제 전 종목·유형·일시·수량·금액 확인
- 모바일에서 저장 CTA가 키보드와 하단 내비게이션에 가려지지 않도록 고정

## 데이터 보호

- 기존 `/api/transactions` POST, PATCH, DELETE 계약을 그대로 사용한다.
- 기존 서버 원장 검증을 최종 검증으로 유지하고 클라이언트 검증은 사용자 안내만 보강한다.
- 데이터베이스 테이블, 칼럼, RLS, 계산식, 거래 저장 형식은 변경하지 않는다.
- 수정·삭제 후 기존 스냅샷 재계산 흐름을 유지한다.

## 자동 검증

- 360px 모바일에서 필드별 오류와 가로 넘침 확인
- 390px 모바일에서 하단 CTA 한 번 탭 진입 확인
- 보유 자산에서 빠른 매도 진입 및 종목·가능 수량 연결 확인
- 유효한 거래 저장과 신규자금 분류 확인
- 연속 저장 동작에도 API 요청이 한 번만 발생하는지 확인
- 기존 거래 수정 요청의 ID와 변경 수량 확인
- 삭제 확인 모달의 대상 정보와 DELETE 요청 ID 확인
- 라이트·다크 테마 및 5개 대표 뷰포트 회귀 확인

## 산출물

- 모바일 거래 UI: `index.html`, `styles.css`, `app.js`
- 배포 빌드: `dist/`
- 거래 E2E: `tests/visual-smoke.mjs`
- 기준 화면: `docs/investment-intelligence/screenshots/phase1b/`

## 잔여 범위

서로 다른 브라우저 탭이나 기기에서 동시에 동일 거래를 전송하는 경우의 서버 멱등성은 데이터베이스 제약 또는 멱등성 키 설계가 필요하다. 이번 단계에서는 기존 스키마를 유지하기 위해 동일 화면의 연속 제출만 차단한다.
