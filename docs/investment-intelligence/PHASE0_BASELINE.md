# Investment Intelligence Platform — Phase 0 기준선

> 작성일: 2026-11-20 KST
>
> 기준 브랜치: `docs/investment-intelligence-a-plus-handoff` (`601a200`)
>
> 목적: A+ 목업을 적용하기 전에 기존 자산관리 기능, 데이터 계약, 테스트 및 Phase 1 변경 경계를 고정한다.

## 1. 결론

- 현재 제품은 단일 사용자의 포트폴리오 관리 웹앱이며, 정적 HTML/CSS/JS와 Sites Worker, Supabase로 구성된다.
- 기존 자산관리·거래·정산·성과·전략 기능은 Phase 1에서도 유지한다.
- A+ HTML은 디자인 및 정보구조 참고 자료다. 합성 시장 데이터와 백테스트 결과를 운영 기능으로 복사하지 않는다.
- Phase 1은 `1A 디자인 시스템·테마`와 `1B 모바일 자산관리·거래 UX`까지만 수행한다.
- 시장 분석, 과거 유사 시장, 전략 연구실은 실제 데이터와 계산 검증이 필요한 후속 Phase로 남긴다.
- Phase 1A는 DB 변경 없이 진행할 수 있다. 기기 간 테마 동기화와 강한 거래 멱등성은 별도 승인 대상이다.

## 3. 현재 아키텍처와 보안 경계

```text
Browser
  ├─ index.html / styles.css / app.js / finance.js
  └─ same-origin /api/*
       └─ Sites Worker (worker.js)
            ├─ HMAC 서명 세션 쿠키
            ├─ 고정 PORTFOLIO_USER_ID 범위 제한
            ├─ Supabase REST/RPC
            ├─ market quotes / portfolio snapshot 함수
            └─ service_role 키는 서버 환경 변수에만 존재
```

현재 로그인은 사용자별 계정 시스템이 아니라 사이트 비밀번호와 고정 운영 사용자 방식이다. 따라서 인수인계 문서의 F-022는 Phase 1에서 다음처럼 해석한다.

- 브라우저에 `service_role` 또는 운영 사용자 UUID를 노출하지 않는다.
- 인증되지 않은 요청은 `/api/*` 데이터에 접근하지 못한다.
- Worker의 모든 DB 요청은 `PORTFOLIO_USER_ID`로 제한한다.
- 다중 사용자 Auth/RLS 제품 전환은 Phase 1 범위에 포함하지 않는다.

## 6. 데이터 모델과 최소 변경 방안

### 저장소에서 확인한 객체

- `transactions`: 기존 테이블에 `reason`, `strategy_cycle_id`, `strategy_trigger`가 추가되어 있다.
- `daily_snapshots`: `net_contributions`, `twr_daily_return`, `twr_coverage_start`가 추가되어 있다.
- `portfolio_strategy_settings`: 사용자별 목표 비중과 Drawdown 설정을 저장한다.
- `settlement_adjustments`: 내부 정산 잔액 보정과 역분개를 저장한다.
- `valuation_events`: 평가 이력 보조 객체가 migration에 존재한다.

### Phase 1A

- DB migration 없음이 기본안이다.
- 테마는 우선 `localStorage`에 `light | dark | system`으로 저장한다.
- 초기 렌더 전에 `<html>`의 테마를 결정해 FOUC를 줄인다.

### 별도 승인 대상

1. 기기 간 테마·레이아웃 동기화
   - 권장: `portfolio_user_preferences` 단일 행 테이블 또는 동등한 사용자 설정 저장소.
   - 거래, 스냅샷, 전략 설정 테이블에 UI 설정을 섞지 않는다.
2. 네트워크 재시도까지 보장하는 거래 멱등성
   - 현재 Worker는 요청마다 거래 UUID를 새로 생성한다.
   - 버튼 연속 탭은 클라이언트 잠금으로 차단할 수 있지만, 타임아웃 후 동일 요청 재전송은 중복 가능성이 있다.
   - 권장: 사용자 범위의 `client_request_id` unique 제약 또는 별도 idempotency 저장소.

어떤 migration도 적용 전에 실제 운영 스키마, 용량, 백업 및 rollback SQL을 별도 검토한다.

## 10. 승인 게이트

Phase 1A를 시작하기 전에 다음을 확정한다.

1. 모바일은 하단 5항목, 태블릿/PC는 A+ 사이드바를 사용한다.
2. Phase 1의 운영 메뉴는 홈·자산·거래·설정으로 제한한다.
3. 라이트 기본값은 A+ 목업, 다크는 현재 네이비 정체성을 토큰화한다.
4. Phase 1A 테마 저장은 우선 localStorage를 사용한다.
5. 기기 간 설정 동기화와 서버 거래 멱등성은 migration 설계 후 별도 승인한다.
6. 단일 계좌·USD·수수료 0이라는 현재 회계 정책을 유지한다.

이 승인 전에는 운영 DB migration이나 시장 분석·백테스트 기능 구현을 시작하지 않는다.
